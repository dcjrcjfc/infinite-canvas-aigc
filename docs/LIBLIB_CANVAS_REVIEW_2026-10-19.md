# LibTV 无限画布：REA 分析与迁移建议

日期：2026-10-19。目标为用户提供的 [LibTV 画布](https://www.liblib.tv/canvas?guideSource=home-feature-grid&spaceId=12173962&projectId=281313d2080b4dd0aaffeaf0c756fc5a)。本轮是调查和建议，没有实施下文功能，也没有调用收费生成、修改参考画布节点或发布分享。

## 结论

它试图解决的是：让创作者把剧本、角色素材、分镜、图像、视频和剪辑组织在一个可追踪、可迭代的制作空间中。

最值得迁移的方向是从“能够摆放和连接节点”走向“能够管理候选结果、保持引用一致、批量推进镜头”。建议保留本项目已经形成的紧凑工作台，把重点放在结果选择、清晰反馈和创作流程上。

## 为什么这些结构有效

### 1. 以创作对象组织界面

R1 的工作流／故事板切换，配合 S4/S6 的表格字段、资产和创意视图，提供不同的工作角度：连线适合看依赖，表格适合连续修改镜头，素材视图适合检查角色和参考。这比让所有事情都在散落的卡片里完成更适合长流程。

**迁移方式 D**：增加同一份镜头数据的“画布／分镜表”视图。表格行和节点用稳定 ID 关联，修改一处能在另一处看到，点击行可定位节点。先做镜号、时长、描述、参考、图片提示词、视频提示词、状态；其他字段按需展开。

### 2. 将创作迭代与最终采用分开

S4 有多结果的主图选择与原图比较组件，S3 的多结果菜单提供展开结果等操作。这说明前端实现有候选内容及选择操作，不能据此扩大为所有类型统一的版本树。

**迁移方式 D**：一个节点保留多个候选与每次生成的参数快照，明确标出“下游采用哪一版”；支持原图／当前结果比较和将候选展开为独立节点。本项目当前生成直接替换媒体，撤销和全局历史不能完全承担这个职责。

### 3. 让依赖变化可见

S4 的节点标题组件接收 `isStale`、`onRetry`、`onDismissStale`，存在输入变更提示，脚本流程使用输入指纹；S5 对应内容更新和需要重算等状态。

**迁移方式 D**：记录生成时的上游输入版本。上游改变后，给下游结果一个轻量更新标记，保留旧结果，由用户决定重跑。手动修改过的提示词应单独提示，避免静默覆盖。验收时重点检查连续变更、撤销、切换候选和刷新恢复。

### 4. 将编辑手势与画布手势分开

S3/S4 有聚焦编辑的返回／退出入口，以及点选、框选、画笔、橡皮、笔刷尺寸、标记和重置状态。编辑模式会约束节点拖动、选择和连接。不能把这些代码等同于后台分割或生成质量已经验收。

**迁移方式 D**：局部编辑进入明确模式，工具条只显示当前需要的工具；Esc 返回原节点和原视口。画笔时不触发框选，输入提示词时不拖画布。先实现真实裁剪与可撤销蒙版，供应商支持后再接局部重绘、消除、扩图和超分。

## UI 与交互：具体值得采用的细节

1. **上下文工具条**：常态简洁，选中图片才显示裁剪／编辑／比较；分组选中才显示运行、布局和工作流保存。我们已有选择操作条，应扩充对象相关行为，而不是再加常驻工具栏。
2. **明确模式**：编辑区显示当前模式、返回和退出。主画布、局部编辑、素材选择使用一致的 Esc 规则，并恢复焦点和视口。参考的模式边界来自 S3/S4，实际动画与焦点路径尚未逐项实测。
3. **长流程的状态密度**：把“排队／生成／失败／输入更新”放在节点附近；详细错误、参数、来源和用量按需展开。已有生成中状态继续保留，不重新塞回重复类型标签。
4. **参考输入可理解**：正文里的引用应是可识别对象，能从已连接来源或资产库选择，能看到主参考与数量限制，而不是只在后台拼接。我们已有主参考和排序，应把来源关系表达得更清楚。
5. **主内容优先的定位**：静态控制条逻辑包含对主节点聚簇的适应处理，避免一张远处遗落节点把所有内容缩成一粒。我们已有“显示全部”，可以增加“适应选区”与“返回上次视图”。
6. **轻量操作反馈**：短提示反馈导入、采用候选、引用和保存，长任务使用可持续状态。没有可靠实测时不照搬动画毫秒数、拖动惯性和亮度参数。

## 推荐落地顺序与验收

**第一阶段：日常使用更省操作。** 批量拖入／粘贴、参考说明节点、可调助手、清晰引用与输入更新提示。完成标准是可撤销、可恢复、不串手势，已有画布数据兼容。

**第二阶段：生成结果能挑选和精修。** 候选结果、采用版本、原图比较、裁剪和局部编辑。先打通结果数据结构，再接支持的模型，确保下游和导出采用正确版本。

**第三阶段：真正的分镜生产。** 分镜表、角色／场景资产、可保存工作流、任务中心和整组执行。先做一条“文本→分镜图→视频→时间线”的受控链，验证失败重试不重复创建或提交任务，随后扩大规模。

每阶段都必须检查导出导入、刷新恢复、撤销重做、旧项目兼容、键盘输入、取消和失败路径；不以静态按钮齐全作为完工。云协作、专业导演动画、社区与商业积分体系可独立评估，当前不宜同时铺开。

## 本轮仍未知的内容

连续拖动的真实帧率与惯性；悬停和菜单的像素精度；不同账号／版本的功能开关；局部编辑的实际生成质量；批量依赖调度与取消的后台保证；协作锁的冲突处理；计费扣除和退款；手机及低性能设备表现。它们需要在稳定可控的浏览器中继续实测，不能由脚本名称或文案推定。
